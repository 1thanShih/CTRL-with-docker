Fix #1 · 安全看門狗：lane_detect 斷訊時自動煞車

最高優先級。原本只有 lane_callback 會發 Twist，lane_detect_v2.py 一旦掛掉就沒人通知 Arduino 停車。

lane_controller_fuzzy.py

safety critical

新增參數

~lane_data_timeout
連續多久沒收到 lane_detect 就視為斷訊（秒，預設 0.3）

新增 Timer + watchdog callback

self.watchdog_timer = rospy.Timer(rospy.Duration(0.1), self._watchdog_cb)
def _watchdog_cb(self, _event):
    # 若 lane_detect 還沒送過任何訊息，watchdog 不主動踩煞車（等啟動）
    if self.last_lane_time <= 0.0:
        return
    # 大轉彎進行中由 lane_callback 的計時邏輯掌控，不要被 watchdog 打斷
    now = rospy.Time.now().to_sec()
    if now < self.hard_turn_end_time:
        return
    if (now - self.last_lane_time) > self.lane_data_timeout:
        rospy.logwarn_throttle(
            1.0,
            "lane_detect stale for %.2fs > %.2fs, publishing zero Twist",
            now - self.last_lane_time, self.lane_data_timeout,
        )
        self._publish(0.0, 0.0)

lane_callback 第一行記錄時間戳

def lane_callback(self, msg):
    now = rospy.Time.now().to_sec()
    with self.state_lock:
        self.last_lane_time = now

State lock (threading.Lock) 是預防之後切換到 MultiThreadedSpinner 時， Timer / Subscriber 同時讀寫 last_lane_time。預設單執行緒下其實不需要，但這層保險近乎免費。

邏輯細節：看門狗有兩個重要的 exception 路徑——啟動前 (last_lane_time == 0) 與 大轉彎進行中。前者避免節點剛起來就把車鎖死、後者避免 hard turn 期間被誤判（hard turn 是 計時驅動，本來就會自己 publish）。

Fix #2 · 尋標掃描 timeout

原本 is_scanning 一旦進入只能靠新的路標訊號清除；路標如果永遠看不到（鏡頭被遮、turn_detect 掛掉），車會永遠原地左右擺。

bug fix

新增參數

~max_scan_duration
掃描尋標的最大持續時間（秒，預設 4.0）；逾時退回一般循線
# 第二優先級：尋標掃描 (停止前進、左右擺動找路標)
if self.is_scanning:
    if (now - self.scan_start_time) > self.max_scan_duration:
        rospy.logwarn("Scan timeout %.2fs exceeded, resuming lane following",
                      self.max_scan_duration)
        self.is_scanning = False
    else:
    self._publish(0.0, self._scan_angular(now))
    return
        self._publish(0.0, self._scan_angular(now))
        return

逾時不直接 return — 讓控制流繼續走到「第四優先級：正常模糊循線」， 車就能用 當下最後一筆 lane 資料繼續往前，而不是僵在掃描狀態。

Fix #3 · lane_detect 量測與 ROI mask 效能

兩個小但每幀都發生的浪費。針對 30 FPS × 640×480 的工作負載，這兩處合起來節省的記憶體寫入量可觀。

lane_detect_v2.py · measure_at_anchor

perf

原本：每側、每幀 rasterize 一張 H×W mask 再切 band

mask = np.zeros((frame_height, frame_width), dtype=np.uint8)
cnt = points.reshape(-1, 1, 2)
cv2.fillPoly(mask, [cnt], 255)
y0 = max(0, anchor_y - band_half)
y1 = min(frame_height, anchor_y + band_half + 1)
band = mask[y0:y1, :]
_, xs = np.where(band > 0)

改為 vectorized 條件遮罩

pts = points.reshape(-1, 2)
ys = pts[:, 1]
band_mask = (ys >= anchor_y - band_half) & (ys <= anchor_y + band_half)
if not band_mask.any():
    return None
return float(pts[band_mask, 0].mean())

每側成本從 O(W·H) 寫入 + O(W·H) 掃描，降為 O(N_points) 比較與平均。 當輪廓只有上千個點時，差距至少一個量級。

lane_detect_v2.py · _build_roi_mask

perf

加上 (h, w, ratios) 為 key 的模組級快取

_ROI_MASK_CACHE: dict[tuple[int, int, tuple[tuple[float, float], ...]], np.ndarray] = {}

def _build_roi_mask(height, width, cfg):
    key = (height, width, cfg.ROI_POLYGON_RATIOS)
    cached = _ROI_MASK_CACHE.get(key)
    if cached is not None:
        return cached
    mask = np.zeros((height, width), dtype=np.uint8)
    ...
    _ROI_MASK_CACHE[key] = mask
    return mask

ROI ratios 是 frozen Config 欄位，runtime 永遠不變，所以 cache 可以無限期保留。 第一次處理新解析度時付一次代價，之後每幀直接命中。

param surface

@dataclass
class TurnParams:

    threshold_method: str = DEFAULT_THRESHOLD_METHOD
    invert_binary: bool = DEFAULT_INVERT_BINARY

    aspect_ratio_max: float = DEFAULT_ASPECT_RATIO_MAX
    area_ratio_min: float = DEFAULT_AREA_RATIO_MIN

附帶修正 · 拿掉 anonymous=True

YAML namespace 對齊的前置條件。三個節點都是 singleton 角色，本來就不該 anonymous。

lane_detect_v2.py · turn_detect.py · lane_controller_fuzzy.py

behavioural 
rospy.init_node('lane_detect_node', anonymous=True)
rospy.init_node('lane_detect_node')

三個節點都做同樣的修改。anonymous=True 會在名稱後加上 PID/timestamp 字尾 （變成 /lane_detect_node_12345_1700000000000）， 導致 yaml 載到 /lane_detect_node/* 的私有參數無法被 rospy.get_param('~xxx') 解析到。三個節點都是單例，把 anonymous 拿掉即可。
